# NIU_B01 六链路静止测试

2026-09-09 北京时间 **12:12:58–12:14:59**，同时采集 ugv2、ugv3 左板、ugv3 右板和 ugv4。
每个设备记录约两分钟，按来源 UID 与对端 UID 提取六条有向链路，得到 **5679 条对端测量记录**。
距离、水平角、RSSI、节点本地时钟、接收时间和用户数据均保留在原始 ROS bag 与 CSV 中。

## 手册依据

[IOT_User_Manual_V1.0.pdf](../logs/uwb_iot/references/IOT_User_Manual_V1.0.pdf)
第 4.1.2 节（印刷第 6 页，PDF 第 7 页）明确写明：

> 对于 NIU_B01 设备可以测量得到通讯范围内其他节点相对于自身的角度，包括横向角度
> aoa_h 与纵向角度 aoa_v。角度有效测量范围为[-50°, 50°]。

本次按 **−50° ≤ 水平角 ≤ +50°** 标记范围状态，完整保存所有输出。
协议表中的角度字段表示范围 [-180°, 180°] 与有效测角范围含义不同。
处于有效范围内只是角度范围检查，并不保证没有遮挡、多径或安装误差。

手册第 3 节还说明：

- UID 出厂唯一且不可更改；`System Time` 为节点本地运行时间，单位毫秒。
- `Telecom Rate` 控制无线测量频率，`Updata Rate` 控制串口输出频率。
- `Output Mode` 会选择随机输出或优先输出近处节点，影响哪些对端出现在一帧中。
- `FilterFactor` 控制设备自身的输出滤波。本次保存设备现有配置下的输出，未额外平滑或剔除样本。

| 设备 | UID | 所在车固定串口 |

| ugv2 | `0x15003B00` | `/dev/uwb_iot` |

角度使用发送该帧的来源设备局部坐标系；左右板分别是两个不同的测量参考点。

## 结果

下表为均值 ± 总体标准差。全部 **5679 条水平角均在 ±50° 内**，所有距离为正且数值有限。

| 方向 | 样本 / 来源总帧数 | 对端出现率 | 距离（m） | 水平角（°） | 最大相邻记录间隔（设备秒） |
|---|---:|---:|---:|---:|---:|
| ugv3_left → ugv2 | 961 / 1225 | 78.4% | 0.6656 ± 0.0179 | 16.73 ± 2.05 | 0.7 |
| ugv2 → ugv3_left | 965 / 1214 | 79.5% | 0.6668 ± 0.0184 | 15.83 ± 2.73 | 0.9 |
| ugv3_right → ugv4 | 949 / 1224 | 77.5% | 0.8482 ± 0.0122 | 4.72 ± 2.56 | 0.6 |
| ugv4 → ugv3_right | 946 / 1219 | 77.6% | 0.8485 ± 0.0122 | 14.02 ± 2.48 | 0.5 |
| ugv2 → ugv4 | 930 / 1214 | 76.6% | 1.4734 ± 0.0128 | −16.80 ± 3.02 | 0.7 |
| ugv4 → ugv2 | 928 / 1219 | 76.1% | 1.4736 ± 0.0123 | 30.04 ± 2.16 | 0.6 |

测距输出标准差约 **1.2–1.8 cm**，水平角标准差约 **2.0–3.0°**。
这描述本次输出的散布，绝对精度仍需要独立测量的距离、角度真值。
同一对设备的双向距离可能相关，双向均值接近不能独立证明绝对精度。

对端出现率是“含该对端的帧数 / 来源总帧数”，受到输出选择等因素影响，不能直接视为无线丢包率。
每个设备的相邻帧 `system_time` 均递增 100 ms，但单条链路并非每帧出现；
相邻对端记录的最长间隔达到 **0.9 设备秒**。消息没有对端独立采样时刻，也不能保证每条记录都是新的测量。

设备本地时间跨度约 121.3–122.4 秒，bag 接收时间跨度约 120.4–120.7 秒。
图中每个来源设备的时间轴独立从首帧归零，尚未进行设备与主机、跨设备时钟标定。

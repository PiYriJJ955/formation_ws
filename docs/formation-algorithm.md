# 当前编队算法与限速

本项目使用领航—跟随的固定相对位移控制。每辆跟随车独立读取领航车状态，
以 20 Hz 计算自己的目标位置和速度，再向本车底盘发布 `Twist`。
领航车由第三页“领航控制”弹窗选择键盘或参考路径控制；编号由第二页选择，与 ROS Master 所在车辆相互独立。

实现：[displacement_follower.py](../src/five_ugv_formation_control/scripts/displacement_follower.py)，
参数：[formation.yaml](../src/five_ugv_formation_control/config/formation.yaml)，
启动入口：[follower.launch](../src/five_ugv_formation_control/launch/follower.launch)。

## 控制器使用的数据

| 输入 | ROS 话题 | 用途 |
| --- | --- | --- |
| 领航车和本车位置 | `/ugvN/uwb/pose` 的 X、Y | 计算目标位置和位置误差 |
| 定位有效性 | `/ugvN/uwb/valid` | 无效时停车 |
| 领航车和本车航向 | `/ugvN/odom_combined` 的四元数 | 航向对齐、旋转队形偏移、计算转向 |
| 两车实测速度 | 各自 `/ugvN/odom` 的 `twist` | 领航轨迹前馈、静止确认、两车状态外推 |
| 本车期望相对位置 | `offset_x`、`offset_y` | 来自车端 `robot.env` 或 GUI 启动设置 |
| 跟随使能 | `/five_ugv_formation/enable` | 控制跟随器运行 / 停车 |
| 本车线速度上限 | `~max_linear` 参数及 `~set_max_linear` 话题 | 最终平移指令限幅 |

定位与控制的航向来源需要区分：鲁棒 UWB EKF 的状态是 `[x, y, yaw]`，
使用固定标签高度和各基站的三维坐标计算距离观测；其 X、Y 用于位置反馈，航向用于初始标定。
控制运行时使用 `robot_pose_ekf` 的 `odom_combined` 航向；自动标定时读取有效 UWB pose
的 orientation，建立里程计到 UWB 地图的固定偏移。

默认 `auto_align_yaw=true`：两车各自静止至少 0.4 秒后，使用 UWB pose 源时间对应的
odom 航向计算 `offset=yaw_uwb-yaw_odom`。禁用期间也可完成标定；使能时尚未完成则
以 `WAIT_ALIGNMENT` 停车等待。领航与跟随使用同一地图标定方法。
UWB 定位初始化的已知朝向要求仍需满足，单标签静止距离观测不能独立提供绝对航向。
若已有外部标定，可设 `auto_align_yaw=false` 并配置两车的固定偏移。
地图箭头在连接监视时单独建立朝向参考；重连地图不会重置控制器内部的航向对齐。

## 每个控制周期的计算

记领航车位置为 $p_L$，对齐后的航向为 $\theta_L$，本车位置为 $p_i$、航向为 $\theta_i$。
$R(\theta)$ 为二维旋转矩阵，$J(x,y)=(-y,x)$。

1. **生成随领航车转动的目标。** 本车偏移 $d_i=(d_x,d_y)$ 定义在领航车坐标系中：

   $$
   p_{d,i}=p_L+R(\theta_L)d_i
   $$

2. **计算目标速度前馈。** 将领航车车体速度旋转到 UWB 地图系，
   并考虑转弯时队形偏移点的切向速度：

   $$
   v_{d,i}=R(\theta_L)v_{L,body}+\omega_L J R(\theta_L)d_i
   $$

   前馈来自里程计实测速度，一阶滤波时间常数为 0.15 秒；运动中的小角速度连续保留。
   静止判定单独进行：平移和角速度连续 0.4 秒低于 0.01 m/s、0.01 rad/s 时确认，
   超过各阈值的 1.5 倍即退出。确认静止后前馈置零。

3. **目标切线参考和差速轨迹跟踪。** 记领航车体系内偏移点速度为
   $q=(v_x-\omega_L d_y, v_y+\omega_L d_x)$，则

   $$
   v_d=\|q\|,\quad \theta_d=\theta_L+\operatorname{atan2}(q_y,q_x),\quad
   \omega_d=\omega_L+\frac{q_x\dot q_y-q_y\dot q_x}{\max(\|q\|^2,0.02^2)}
   $$

   $\dot q$ 从滤波里程计速度的变化计算，不对 UWB 位置求导。匀速恒曲率转弯时
   $\omega_d=\omega_L$。将位置误差转到本车坐标系得到 $(e_x,e_y)$，
   $e_\theta=\operatorname{wrap}(\theta_d-\theta_i)$，运动控制律为：

   $$
   v=v_d\cos e_\theta+0.5e_x,\qquad
   \omega=\omega_d+8.0v_de_y+1.2\sin e_\theta
   $$

4. **低速捕获与最终朝向。** 当目标速度从 0 增至 0.02 m/s，使用三次平滑权重
   从位置捕获过渡到轨迹跟踪。位置捕获沿 $u_i=v_{d,i}+0.5(p_{d,i}-p_i)$ 行驶，
   其转向增益也在 $\|u_i\|$ 接近零时平滑归零，避免小向量方向跳变。
   运动中以目标切线为参考，进入 HOLD 后才同步 `领航航向 + offset_yaw`。

5. **生成 mini_4wd 底盘指令。** 航向误差从 0.55 增至 0.95 rad 时平滑降低目标线速度；
   达到 0.95 rad 进入原地对齐，降至 0.55 rad 退出。跟随车仅前进，角速度上限 0.8 rad/s。
   正常线、角加减速度分别限制为 0.15 m/s²、0.8 rad/s²。
   HOLD 位置锁定、更低的硬限速、禁用和输入失效停车优先于平滑。
   领航键盘仍可前进、后退，两个方向均受领航车自身上限约束。

## 到位、停留与输入保护

| 状态 / 条件 | 行为 |
| --- | --- |
| `DISABLED` | 默认不使能，禁用时发送零速度 |
| `FOLLOWING` | 距目标至少 `approach_distance=0.50 m`，使用轨迹跟踪 / 低速捕获 |
| `APPROACH` | 距目标小于 0.50 m，运动控制律与 FOLLOWING 相同 |
| `HOLD` | 领航车静止，且距离目标 ≤0.10 m 连续保持 0.4 秒；平移为零 |
| 退出 `HOLD` | 领航车开始移动，或位置误差 >0.18 m |
| `HOLD` 中朝向修正 | 5° 死区，角速度上限 0.35 rad/s |
| `UWB_INVALID` | 本车或领航车定位无效，发送零速度 |
| `STALE_OR_MISSING_INPUT` | 两车位置、航向、速度的源时间或 valid 接收时间超过 `data_timeout`（默认 0.6 秒），发送零速度 |
| `WAIT_ALIGNMENT` | 等待两车静止并完成 UWB 地图航向标定 |
| `INPUT_TIME_SKEW` | UWB 源时间无法与航向历史在允许外推范围内对应 |

控制器按消息源时间判断位姿和速度新鲜度，拒绝零时间戳、未来帧及重复 / 乱序更新。
各车时钟需同步。使用里程计恒速模型向当前时刻外推，最多 `prediction_limit=0.2 s`；
超出该范围的剩余延迟仍可能造成误差，不等同于严格传感器同步。
valid 消息没有 header，使用接收时间。GUI 也会检查遥测消息年龄。
领航键盘指令的远端有效期为 0.4 秒。平移和转向按键可以组合，分别控制线速度与角速度；
松开一个键只取消对应分量，全部松开、失焦或离开控制区后平移与转向归零。
控制心跳超过 0.4 秒会停车并禁用跟随；远端监视连续 3 秒收不到输入时退出并向各车发零速度。

## 领航车折线路径跟踪

实现：[leader_tracker.py](../scripts/leader_tracker.py)，由 [fleet_ros.py](../scripts/fleet_ros.py)
在 Master 主机的同一个监视进程中以 20 Hz 调用。它计算自动速度，监视进程统一选择键盘或路径输出，
每个周期只向领航车发布一条最终速度。GUI 遥测约 10 Hz。

路径由 2–50 个 UWB 地图坐标点组成，相邻点至少间隔 0.15 m。“使用当前位置为起点”填入当前领航位置，
保持后续点供编辑。开始时车辆应在首点 0.5 m 内；路径按实际位置推进，不要求固定时刻到达某点。
每次预览与开始检查基站矩形范围，留出 0.15 m 车体余量；跟随使能时再加上最大编队偏移半径，
为转弯中的整个队形留空间。该检查是保守边界检查，不包含障碍物规划。

路径控制位置取 UWB EKF 的 X、Y，航向取 `odom_combined`：监视连接后，领航车静止至少 0.4 秒时，
用有效 UWB EKF 航向建立一次固定偏移，将里程计航向对齐到 UWB 地图。
切换控制模式、暂停和继续都保留该偏移；重连时重新等待静止对齐，不把任意当前朝向置为 +X。
因此地图领航箭头使用该控制航向，跟随车箭头仍沿用原有连接时参考。

每周期只在已完成弧长前后的小窗口内搜索投影点，前向窗口为预瞄距离，进度只向前推进。
目标点位于进度前方 0.3–0.5 m，默认 0.4 m。将目标点转换到车体系得到 $(x_b,y_b)$：

$$
\kappa=\frac{2y_b}{x_b^2+y_b^2},\qquad \omega=\kappa v
$$

航向误差超过 0.7 rad 时先原地转向；跟踪时按曲率限制速度，接近终点按剩余距离减速。
到终点 0.10 m 内且进度接近末段时完成。预瞄跨过折线拐点会产生平滑切弯。
正常线加减速度为 0.15 m/s²，角加减速度为 0.8 rad/s²，路径控制角速度上限为 0.5 rad/s；
停车和新的更低硬上限优先。

跟随使能时，领航速度还需满足各跟随车偏移点的速度预算：

$$
v\sqrt{(1-\kappa d_y)^2+(\kappa d_x)^2}\le0.8v_{\max,i}
$$

原地转向时限制 $|\omega|\sqrt{d_x^2+d_y^2}\le0.8v_{\max,i}$；
最终输出再次检查实际 $(v,\omega)$ 对应的偏移点速度，留出 20% 余量用于位置误差修正。
这限制的是前馈需求，实际整队效果仍受定位、转向过程和底盘响应影响。

定位无效、输入超过可调的 `data_timeout`（默认 0.6 秒）、位置突变、局部路径误差超过 0.6 m、速度上限为零、底盘断开或控制心跳超时
会将路径置为 `PAUSED`，输出零速度。定位恢复或心跳恢复都不会自行恢复行驶，必须点击“继续”。
跟随使能时还检查所有跟随车定位、限速回读及队形边界。关闭弹窗会暂停，停止后须重新开始路径。
每次开始记录路径配置及 20 Hz CSV；日志包含进度、横向距离误差、航向误差、实际输出、线速度上限和状态。

## 第三页的全车线速度上限

在“全车线速度上限”中输入一个数值，点击“应用到全部”，统一设置领航车和所有跟随车。默认 0.15 m/s，
允许 0–0.5 m/s，保存后重开软件可恢复。设为 0 限制平移，键盘转向仍可用，路径跟踪会暂停；
停车按钮同时处理转向和跟随使能。

- 统一上限保存在主机设置中，重开软件、车辆改名或新增车辆后均沿用；启动时向本次参与车辆下发。
- 领航车键盘请求在主机与远端监视脚本中限幅；跟随车在控制器最终输出处限幅，
  收到新值后的控制周期即使用新上限。
- 在线值通过 `/ugvN/formation_controller/set_max_linear`（`std_msgs/Float64`）发送。
  控制器更新内存及 ROS 参数后，在 `/ugvN/formation_controller/max_linear` 回读确认。
  后者是锁存话题，同时进入编队 CSV 的 `max_linear` 列。
- 同一行显示已生效数量和待确认车辆；确认需要当前连接有效且回读值匹配。跟随控制器缺少支持或尚未启动时显示待确认，
  编队使能会被拒绝。离线车辆保留设置，在下次 GUI 启动该车时应用。
- 本功能约束第三页领航键盘、路径跟踪和编队跟随输出；从其他程序直接发布的速度指令不经过这些限幅。
  命令上限也不代表车体实测速度会瞬间降到上限，底盘仍有加减速过程。
- 手动使用 `roslaunch` 可传入 `max_linear:=0.15`；GUI 的记忆保存在主机设置中，
  独立于手工启动命令。一次会话中的在线限速修改无需重启控制器。

首次升级需要主机重开 GUI，并让车端更新跟随器及 launch 文件后重新启动。
更新程序会等待正在运行的 ROS 任务结束，再应用已发布版本。

## 限速与跟踪滞后的关系

直线匀速时，跟随车既要达到领航速度，又要用额外速度消除位置误差。
例如领航车约 0.20 m/s、跟随上限 0.15 m/s 时，跟随车持续饱和也无法追上持续前进的目标。
转弯时还需留出 $|\omega_L|\,\|d_i\|$ 对应的切向速度余量，队形外侧车辆往往更容易饱和。

建议先把全车上限设为 0.15 m/s，领航键盘请求速度设为 0.10–0.12 m/s 做对照实测，再按误差和饱和比例调整。
调整上限不会改变位置增益、转向阈值或 `HOLD` 条件，也无法修复定位跳变和航向误差。
分析时应同时查看 CSV 的 `max_linear`、实际指令、位置误差、控制器状态及 UWB 有效性。

当前算法的适用前提是场地内无障碍、通信和定位可用，队形目标可达到；
实现中没有碰撞避让、路径规划或对受限运动的滚动优化。

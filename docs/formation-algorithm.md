# 当前编队算法与限速

本项目使用领航—跟随的固定相对位移控制。每辆跟随车独立读取领航车状态，
以 20 Hz 计算自己的目标位置和速度，再向本车底盘发布 `Twist`。
领航车由第三页键盘控制；领航车编号由第二页选择，与 ROS Master 所在车辆相互独立。

实现：[displacement_follower.py](../src/five_ugv_formation_control/scripts/displacement_follower.py)，
参数：[formation.yaml](../src/five_ugv_formation_control/config/formation.yaml)，
启动入口：[follower.launch](../src/five_ugv_formation_control/launch/follower.launch)。

## 控制器使用的数据

| 输入 | ROS 话题 | 用途 |
| --- | --- | --- |
| 领航车和本车位置 | `/ugvN/uwb/pose` 的 X、Y | 计算目标位置和位置误差 |
| 定位有效性 | `/ugvN/uwb/valid` | 无效时停车 |
| 领航车和本车航向 | `/ugvN/odom_combined` 的四元数 | 航向对齐、旋转队形偏移、计算转向 |
| 领航车实测速度 | 领航车 `/ugvN/odom` 的 `twist` | 平移和转动前馈 |
| 本车期望相对位置 | `offset_x`、`offset_y` | 来自车端 `robot.env` 或 GUI 启动设置 |
| 跟随使能 | `/five_ugv_formation/enable` | 控制跟随器运行 / 停车 |
| 本车线速度上限 | `~max_linear` 参数及 `~set_max_linear` 话题 | 最终平移指令限幅 |

定位与控制的航向来源需要区分：鲁棒 UWB EKF 的状态是 `[x, y, yaw]`，
使用固定标签高度和各基站的三维坐标计算距离观测；控制器只取其输出的 X、Y。
**当前控制器的航向来自 `robot_pose_ekf` 输出的 `odom_combined`，不读取 UWB pose 的 orientation。**
因此，UWB 距离对定位 EKF 航向的间接修正，没有直接进入编队控制的航向输入。

默认 `auto_align_yaw=true`：每个跟随控制器将首次接收到的本车、领航车航向
分别对齐到 `initial_uwb_yaw=0`。启动前车辆应朝向 UWB 地图 +X。
启动朝向有偏差或后续航向漂移，会影响队形旋转和转向控制。
地图箭头在连接监视时单独建立朝向参考；重连地图不会重置控制器内部的航向对齐。

## 每个控制周期的计算

记领航车位置为 $p_L$，对齐后的航向为 $\theta_L$，本车位置为 $p_i$、航向为 $\theta_i$。
$R(\theta)$ 为二维旋转矩阵，$J(x,y)=(-y,x)$。

1. **生成随领航车转动的目标。** 本车偏移 $d_i=(d_x,d_y)$ 定义在领航车坐标系中：

   $$
   p_{d,i}=p_L+R(\theta_L)d_i
   $$

2. **计算目标速度前馈。** 将领航车车体速度旋转到 UWB 地图系，
   并考虑转弯时队形偏移点的切向速度：

   $$
   v_{d,i}=R(\theta_L)v_{L,body}+\omega_L J R(\theta_L)d_i
   $$

   领航车实测平移速度模长小于 0.03 m/s、角速度绝对值小于 0.03 rad/s 时分别置零，
   避免静止噪声不断推动队形。前馈来自里程计实测速度。

3. **位置误差反馈。**

   $$
   e_i=p_{d,i}-p_i,\qquad u_i=v_{d,i}+0.8e_i
   $$

   $u_i$ 是期望的平面速度向量，尚未经过底盘运动约束。

4. **协调行驶方向与最终朝向。** 当 $\|u_i\|\ge0.02$ m/s 时，
   由 `atan2(u_y,u_x)` 得到行驶方向。距离目标小于 0.50 m 后，
   用三次平滑函数逐渐混入领航车航向加 `offset_yaw`，权重最高 0.35。
   角度按最短转向插值；转向增益从 1.8 向 1.2 混合，加入按权重缩放的领航车角速度前馈。
   正常行驶时角速度限制为 ±0.8 rad/s。

5. **生成 mini_4wd 底盘指令。** 航向误差超过 0.7 rad（约 40°）时先原地转向。
   允许前进后，将平面速度投影到本车朝向并限幅：

   $$
   v_i=\operatorname{clip}
   \left(u_i^T[\cos\theta_i,\sin\theta_i]^T,\;0,\;v_{\max,i}\right)
   $$

   跟随车只向前行驶；目标落在身后时需要先转向。领航键盘可前进、后退，
   两个方向均受领航车自身上限约束。
   当期望平面速度低于 0.02 m/s 时，平移输出为零，改用领航车角速度和航向同步误差控制转向。

## 到位、停留与输入保护

| 状态 / 条件 | 行为 |
| --- | --- |
| `DISABLED` | 默认不使能，禁用时发送零速度 |
| `FOLLOWING` | 距目标至少 0.50 m，主要按位置误差追踪 |
| `APPROACH` | 距目标小于 0.50 m，逐渐增加朝向同步权重 |
| `HOLD` | 领航车静止，且距离目标 ≤0.10 m 连续保持 0.4 秒；平移为零 |
| 退出 `HOLD` | 领航车开始移动，或位置误差 >0.18 m |
| `HOLD` 中朝向修正 | 5° 死区，角速度上限 0.35 rad/s |
| `UWB_INVALID` | 本车或领航车定位无效，发送零速度 |
| `STALE_OR_MISSING_INPUT` | 位置、航向或领航实测速度超过 0.5 秒未收到，发送零速度 |

控制器当前按回调接收时间判断输入新鲜度，没有按各传感器源时间戳做严格同步。
GUI 显示与使能检查还会检查遥测中的消息年龄。
领航键盘指令的远端有效期为 0.4 秒；松键、失焦或离开控制区后平移与转向归零。
GUI 心跳超时会关闭监视并禁用跟随；远端监视连续 3 秒收不到输入时退出并向各车发零速度。

## 第三页的全车线速度上限

在“全车线速度上限”中输入一个数值，点击“应用到全部”，统一设置领航车和所有跟随车。默认 0.15 m/s，
允许 0–0.5 m/s，保存后重开软件可恢复。设为 0 仅停止平移，停车按钮同时处理转向和跟随使能。

- 统一上限保存在主机设置中，重开软件、车辆改名或新增车辆后均沿用；启动时向本次参与车辆下发。
- 领航车键盘请求在主机与远端监视脚本中限幅；跟随车在控制器最终输出处限幅，
  收到新值后的控制周期即使用新上限。
- 在线值通过 `/ugvN/formation_controller/set_max_linear`（`std_msgs/Float64`）发送。
  控制器更新内存及 ROS 参数后，在 `/ugvN/formation_controller/max_linear` 回读确认。
  后者是锁存话题，同时进入编队 CSV 的 `max_linear` 列。
- 同一行显示已生效数量和待确认车辆；确认需要当前连接有效且回读值匹配。跟随控制器缺少支持或尚未启动时显示待确认，
  编队使能会被拒绝。离线车辆保留设置，在下次 GUI 启动该车时应用。
- 本功能约束第三页领航键盘和编队跟随输出；从其他程序直接发布的速度指令不经过这些限幅。
  命令上限也不代表车体实测速度会瞬间降到上限，底盘仍有加减速过程。
- 手动使用 `roslaunch` 可传入 `max_linear:=0.15`；GUI 的记忆保存在主机设置中，
  独立于手工启动命令。一次会话中的在线限速修改无需重启控制器。

首次升级需要主机重开 GUI，并让车端更新跟随器及 launch 文件后重新启动。
更新程序会等待正在运行的 ROS 任务结束，再应用已发布版本。

## 限速与跟踪滞后的关系

直线匀速时，跟随车既要达到领航速度，又要用额外速度消除位置误差。
例如领航车约 0.20 m/s、跟随上限 0.15 m/s 时，跟随车持续饱和也无法追上持续前进的目标。
转弯时还需留出 $|\omega_L|\,\|d_i\|$ 对应的切向速度余量，队形外侧车辆往往更容易饱和。

建议先把全车上限设为 0.15 m/s，领航键盘请求速度设为 0.10–0.12 m/s 做对照实测，再按误差和饱和比例调整。
调整上限不会改变位置增益、转向阈值或 `HOLD` 条件，也无法修复定位跳变和航向误差。
分析时应同时查看 CSV 的 `max_linear`、实际指令、位置误差、控制器状态及 UWB 有效性。

当前算法的适用前提是场地内无障碍、通信和定位可用，队形目标可达到；
实现中没有碰撞避让、路径规划或对受限运动的滚动优化。
